# In-Context Learning Creates Task Vectors

## Metadata
**Authors:** Roee Hendel, Mor Geva, Amir Globerson
**Year:** 2023
**arXiv:** https://arxiv.org/abs/2310.15916
**Published venue:** Findings of EMNLP 2023
**DOI:** 10.18653/v1/2023.findings-emnlp.624
**Publisher / proceedings:** ACL Anthology
**Publication status:** PUBLISHED
**Reading status:** FULL_TEXT

## Abstract
The paper proposes that ICL often compresses demonstrations into a single task vector θ(S), which modulates a transformer used to answer a query.

## Scientific question
What hypothesis class or computational representation do LLMs use when learning from demonstrations in context?

## Main claims
- **AUTHOR CLAIM:** Across models and tasks, ICL can often be approximated by a query-conditioned transformer whose behavior is controlled by a task vector computed from the demonstrations.
- **AUTHOR CLAIM:** The representation is useful for interpreting ICL as compression of a training set into task-specific state.

## Key observations
- A separated procedure extracts an activation-space vector from demonstrations using a dummy query, patches it into a later pass that sees only the query, and retains about 80–90% of regular ICL accuracy across reported models/tasks (Sections 3.1–3.4, Fig. 4).
- Injecting a vector for task B while demonstrations specify task A yields high accuracy on task B in tested conflicting-task cases (Section 5, Table 2).

## Evidence for major claims
- **OBSERVATION:** Model outputs under task-vector constructions track outputs from demonstration prompts in the reported experiments.
- **AUTHOR INTERPRETATION:** The agreement indicates that demonstrations induce a compact task representation rather than requiring all examples to remain functionally active.
- **OBSERVATION:** The rule-application pass is constructed without direct access to demonstrations.
- **AUTHOR INTERPRETATION:** The result supports a query-agnostic learning algorithm A(S) and rule-application function f(x; θ).

## Observation vs interpretation
### Observed / demonstrated
- Reported experiments compare prompt-conditioned behavior with behavior using extracted task vectors.
### Author interpretation
- ICL frequently acts as set-to-vector compression followed by query processing.
- The paper operationalizes θ as an intermediate activation; it does not establish that the underlying computation is localized to one object or excludes distributed circuitry.

## Important controls
- Regular ICL, the separated hypothesis procedure, and a no-demonstration baseline are compared (Section 3.4, Fig. 4). Conflicting-task injection tests whether θ overrides the demonstrations’ task (Section 5, Table 2).

## Critical assumptions
- Approximate behavioral agreement is treated as evidence for a task-vector representation.
- The chosen extraction/probing procedure captures the task information relevant to the tested queries.

## Remaining alternative explanations
- Similar outputs could arise from other distributed prompt-compression or retrieval mechanisms.

## Limitations
- “Often” is task/model dependent; the paper does not establish that all ICL uses one vector or that the vector is causally sufficient in every setting.

## What this paper supports
- Task-vector representations are a plausible compact description of some LLM ICL behavior.

## What this paper does NOT establish
- A universal mechanism for ICL, biological/neural equivalence, or generalization beyond tested models/tasks.

## Explicit open questions
- How task vectors are formed internally and when they fail to summarize demonstrations.

## Evidence concerns
**Replication:** Multiple reported settings; independent replication not assessed here.
**Measurement limitations:** Behavioral approximation may underdetermine mechanism.
**Potential confounding:** Task-vector extraction choices and task distributions.
**Statistical / experimental concerns:** Exact uncertainty and ablation details need full-text checking.
